# Targaryen

Product intent and architecture.

> I'm going to break the wheel.

Motto: character quotation; see [provenance](../sources.md).

## When to use

New products, changes to product scope, architecture, boundaries or contracts.

## Axioms

1. **Intent precedes implementation.** A PRD defines the problem, users, desired outcomes, scope and constraints.
2. **Architecture is deliberate.** A design document explains boundaries, ownership, contracts, data flow and important tradeoffs.
3. **The product has one coherent model.** Components and interfaces follow the architecture; resolve competing definitions explicitly.
4. **Recurring problems demand structural answers.** Replace the design that produces them, with a verified migration and retirement of the old path.

## Application and evidence

Reference the current PRD and design document. Reuse existing documents for a scoped change; update them when intent or architecture changes. Keep a small design small, but make decisions explicit. Establish migration and compatibility evidence before replacing a structure.
