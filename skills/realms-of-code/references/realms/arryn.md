# Arryn

Standards and interoperability.

> As High as Honor.

## The lore

From the Eyrie, the realm must be able to see the same horizon. A protocol, format or public contract is a shared measure: builders far apart can meet without guessing. Arryn holds that measure high and demands evidence that every bridge reaches the other side.

## Axioms

1. **Look for the established standard first.** Prefer recognized protocols, formats and conventions.
2. **Conformance is demonstrated.** Validate contracts and interoperability where they matter.
3. **Exceptions need reasons.** Record why a standard does not fit and what maintaining the alternative entails.
4. **Compatibility is an explicit promise.** Version and evolve public contracts deliberately.

## What to do

1. **Find what already exists.** Inspect project conventions, then find applicable standards and existing libraries, protocols or services that implement them. Consult their official specifications and documentation before inventing a format or implementation.
2. **Check current viability.** Verify specification status, supported versions, deprecations, replacements and the implementation's maintenance/security support. Check platform fit, interoperability, licensing and operational constraints. Avoid adopting deprecated or unmaintained options; flag an inherited dependency and plan migration when the requested work requires it.
3. **Reuse the supported path.** Prefer an existing compatible implementation and its defaults. Prototype the uncertain integration and validate real inputs/outputs before committing to it. Record a concrete gap before choosing custom behavior.
4. **Prove compatibility.** Add schema/conformance and round-trip tests across the actual boundary; cover version upgrades and backwards compatibility where promised. Record the selected specification/version and any justified deviation.

## Evidence

Record the chosen standard/version, current support evidence, reuse decision and passing conformance or interoperability checks.
