# Baratheon

Sprints, spikes and agile delivery.

> Ours is the Fury.

## The lore

Storm's End gives fury a direction. A campaign has an objective; each march has an owner and a finish. Sprinty carries the battle plan through sprints and subsprints. Spikes send scouts into uncertainty, and each return changes the plan with evidence.

## When to use

Implementation planning, feature/fix/refactor work, release preparation and bounded investigations.

## Axioms

1. **Implementation belongs to a sprint.** Use Sprinty to make goals, scope, ownership and progress explicit.
2. **Subsprints have coherent outcomes.** Break them into bounded items with dependencies and acceptance evidence.
3. **Spikes answer questions.** Bound the investigation and end with findings, a decision and a next step.
4. **Adapt visibly.** Record scope changes and use retrospectives to improve how subsequent work proceeds.

## Application and evidence

Call Sprinty info first. Discover the current tool contracts; bind explicitly to the correct repository/data directory and resume suitable existing work. Create or identify the owning item before edits, and claim it if the installed workflow requires that. Capture gates and evidence before completion. If a server is bound to another repository, follow its supported binding workflow; do not silently create items in the wrong project. If Sprinty is unavailable, state that and use the smallest temporary tracker allowed by project instructions, then migrate it when available. Do not install a server automatically. The skill does not itself authorize spawning agents.
